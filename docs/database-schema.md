# MediBridge AI - Database Schema (v2)

Database: Supabase (PostgreSQL)

---

# Security Architecture

Sensitive patient information is protected using field-level encryption.

## Encryption

Algorithm:

AES-256-GCM(planned)

Encrypted Fields:

* phone_number
* summary
* patient_explanation

## Hashing

Algorithm:

SHA-256

Hashed Fields:

* phone_number

Hashing enables efficient user lookup without exposing plaintext phone numbers.

---

# Table: users

Stores patient information.

| Column          | Type          |
| --------------- | ------------- |
| id              | UUID (PK)     |
| phone_hash      | TEXT (UNIQUE) |
| phone_encrypted | TEXT          |
| created_at      | TIMESTAMP     |

---

# Table: reports

Stores processed medical submissions.

| Column              | Type                 |
| ------------------- | -------------------- |
| id                  | UUID (PK)            |
| user_id             | UUID (FK → users.id) |
| category            | TEXT                 |
| title               | TEXT                 |
| summary             | TEXT                 |
| patient_explanation | TEXT                 |
| doctor_notes        | TEXT                 |
| input_type          | TEXT                 |
| source_url          | TEXT                 |
| status              | TEXT                 |
| ai_model            | TEXT                 |
| created_at          | TIMESTAMP            |
Security Note:

summary and patient_explanation are encrypted at the application layer before being stored in Supabase.
The database stores ciphertext and does not perform encryption itself.

# Table: extracted_data

Stores individual medical values extracted by AI.

| Column      | Type                   |
| ----------- | ---------------------- |
| id          | UUID (PK)              |
| report_id   | UUID (FK → reports.id) |
| field_name  | TEXT                   |
| field_value | TEXT                   |
| status      | TEXT                   |

---

## Example Data

| field_name  | field_value | status |
| ----------- | ----------- | ------ |
| Hemoglobin  | 9.8         | LOW    |
| Cholesterol | 250         | HIGH   |
| WBC Count   | 12000       | HIGH   |

---

# Relationships

users

└── reports

  └── extracted_data

---

## Relationship Rules

One user can have many reports.

One report can have many extracted medical values.

Each extracted medical value belongs to exactly one report.

# Notes

doctor_notes is reserved for healthcare professionals and should NOT be generated by Gemini AI.

status is used to track processing lifecycle:

RECEIVED → PROCESSING → COMPLETED / FAILED

ai_model stores the Gemini model version used during report generation.

summary and patient_explanation are encrypted before being stored in Supabase.

phone_number is never stored in plaintext.

User lookup is performed using SHA-256 hashes.
